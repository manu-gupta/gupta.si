The Security Architecture of AI Agents

AI agents can act across systems. Security must therefore move from protecting applications to controlling actions.

2026 · RESEARCH NOTE6 min READ

AI agents can act across systems. Security must therefore move from protecting applications to controlling actions.

The new boundary

AI agents are different from ordinary software because they can take action. A normal application may show a screen or return an answer. An agent can read context, decide what to do next, and use several tools on the way. That changes the security boundary.

The important question is no longer only whether a system can be accessed. It is what the system is allowed to do after access. If an agent can read email, create tickets, change a database record and call an external API, each action becomes part of the security model.

The useful security question is simple: who is acting, what can it reach, and what can it change?

Identity and permissions

A user login is only the beginning. An enterprise needs to know which human, application and agent initiated an action; which permissions were available; and whether the action was approved. Short-lived credentials and narrow permissions become more important as agents become more capable.

Approval by risk

Not every action needs a human. But high-impact actions should have stronger controls. A payment, deletion, production change or external communication should not be treated like a low-risk search. The right design is a ladder of approval based on possible impact.

A practical test

A security review for an agent should ask four questions: Who is acting? What can it reach? What can it change? Can we reconstruct what happened? If the answers are unclear, the system is not ready for broad autonomy.
